.. _permissions_cli:

permissions
***********


.. rubric:: Description




The CLI command :code:`permissions` reads and changes, at run time, the
:term:`permissions` attribute of a node, or the attribute of the server
(the path :code:`/`).

The command acts on the whole list of one attribute, at exactly one path:

 - :code:`create`, :code:`update` and :code:`delete` change the attribute, and require the role :code:`p`
 - :code:`read` prints the attribute, and :code:`effective` the roles a user holds at the path; both require the role :code:`r`

.. code-block:: shell

    ecflow_client --permissions create /suite alice:rwxp,bob:r
    ecflow_client --permissions effective /suite/family bob

The rules of the attribute are described in :ref:`permissions_attribute`,
and the validation of every change in :ref:`permissions_attribute_changes`.



.. rubric:: Output of :code:`--help=permissions`



The following help text is generated by :code:`ecflow_client --help=permissions`

::


   permissions
   -----------

   Read or change the Permissions attribute of a node, or of the server

   The operations act on the whole list of the attribute, at exactly one path;
   '/' addresses the server attribute.

   Argument(s):

       --permissions <operation> <path> [<value>] [--fmt cli|json]

   Operations:

       create     Give the node an attribute, holding <value>; fails when the node already has one
       read       Print the attribute of the node; fails when the node has none
       update     Replace the attribute of the node with <value>; fails when the node has none
       delete     Remove the attribute of the node, which then inherits from above;
                  fails when the node has none
       effective  Print the effective roles of the user named by <value> at the path;
                  the requester when <value> is omitted

   The value of create and update is a list of entries, either in the command-line form
   (e.g. alice:rwxp,bob:r) or in the JSON form
   (e.g. '[{"user": "alice", "permissions": "rwxp"}]').

   --fmt selects the format of what read and effective print: cli (the default) or json.

   This command can fail because:
   - the path names no node
   - at the server ('/'), create and delete always fail: the server attribute is configured
     at start-up, in the server configuration file
   - the value is invalid, or names a user not listed above the node
   - on a server without a server attribute, node attributes cannot be created, and effective
     fails: the server does not use Permissions attributes
   - the change would leave a node, or the server, without any user holding p

   After a change, the clients receiving the nodes concerned (every client, for a change of
   the server attribute) synchronise fully at their next request.

   Usage:

       --permissions create /s alice:rwxp,bob:r
       --permissions read /s --fmt json
       --permissions effective /s/f bob
       --permissions update / admin:rwxlops,alice:rwxp,bob:r

   Roles required, when the server uses Permissions attributes:

       read, effective: r at each node addressed (the server for '/')
       create, update, delete: p at each node addressed (the server for '/')

   In whitelist mode, r requires read access, and the other roles write access.

   The client considers, for both user and task commands, the following environment variables:

     ECF_HOST <string> [mandatory*]
       The main server hostname
       Default: localhost
     ECF_PORT <int> [mandatory*]
       The main server port
       Default: 3141
     ECF_SSL <any> [optional*]
       Enable secure communication. Empty or '1': server.crt first; other values: <host>.<port>.crt first.
     ECF_SSL_DIR <string> [optional]
       Directory of the SSL certificates, with or without a trailing '/'. Does not enable SSL.
       Default: $HOME/.ecflowrc/ssl/
     ECF_HOSTFILE <string> [optional]
       File that lists alternate hosts to try, if connection to main host fails
     ECF_HOSTFILE_POLICY <string> [optional]
       The policy ('task' or 'all') to define which commands consider using alternate hosts.
       Default: task
     ECF_TIMEOUT <int> [optional]
       Maximum time for a task command to deliver a message to the server,
       retrying the main and alternate hosts until the limit is reached.
       Also applies to user commands, when ECF_HOSTFILE_POLICY is 'all'.
       Default: 3600 seconds; accepted range: 60 to 86400 seconds
     ECF_CONNECT_TIMEOUT <int> [optional]
       Maximum time for each step of an exchange with the server: connecting,
       sending the request, and receiving the reply (for HTTP/HTTPS, each wait
       for data). The value 0 applies the timeout of the command being executed,
       for example:
         - 10 seconds for --ping
         - 60 seconds for most user commands
         - 190 seconds for task commands
       Default: 0 seconds

   The options marked with (*) must be specified in order for the client to communicate
   with the server, either by setting the environment variables or by specifying the
   command line options.
